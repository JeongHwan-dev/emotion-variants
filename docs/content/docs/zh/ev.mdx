用一个配置对象创建类型安全的样式函数。

```typescript
const button = ev(config);
```

## 用法

### `ev(config)` [#ev-config]

当组件有多个视觉维度（尺寸、颜色、填充、状态），并且你希望把它们都声明在一处时，使用 `ev`。它返回一个函数，传入 variant 值调用后，结果可以直接交给 Emotion 的 `css` prop。

```typescript
import { ev } from 'emotion-variants';

const button = ev({
  base: {
    padding: '10px 20px',
    borderRadius: 8,
    cursor: 'pointer',
  },
  variants: {
    size: {
      small: {
        fontSize: 12,
      },
      large: {
        fontSize: 16,
      },
    },
    color: {
      primary: {
        background: 'blue',
        color: 'white',
      },
      secondary: {
        background: 'gray',
        color: 'white',
      },
    },
  },
  defaultVariants: {
    size: 'small',
    color: 'primary',
  },
});
```

配置对象是必需的。如果暂时没有要声明的内容，传入 `ev({})` 即可。

#### 参数

- `config.base` (`CSSObject`)：每次调用都会应用的样式。在 `ev()` 运行时序列化一次，而不是每次调用都序列化。
- `config.variants` (`Record<string, Record<string, CSSObject>>`)：variant 维度。每个维度把值映射到对应的样式。由于值是对象的键，Boolean 和数字值要写成键，如 `true`、`false`、`1`，它们的类型会还原为 `boolean` 和数字字面量。
- `config.compoundVariants` (`Array<{ variants, style }>`)：只在列出的所有 variant 值都匹配时才应用的样式。条件也可以是一个值数组，匹配其中任意一个即可。注意键名是单数形式的 `style`。
- `config.defaultVariants` (`Partial<Record<Axis, Value>>`)：调用方省略某个维度时使用的值。
- `config.slots` (`Record<string, CSSObject>`)：多元素组件的各个部分及其 base 样式。它替代 `base`，并让每个 variant 值和 compound 的 `style` 都以 slot 名为键。参阅 [Slots](#slots)。
- `config.compoundSlots` (`Array<{ slots, variants?, style }>`)：应用到多个 slot 的同一样式，可以始终生效，也可以只在 `variants` 匹配时生效。必须配合 `slots` 使用。
- `config.extend` (`EvFunction | EvSlotsFunction`)：作为基础的另一个 `ev()` 结果。它的样式、variants、compound variants 和 default variants 都会被继承。参阅 [extend](#extend)。

#### 返回值

(`EvFunction<T>`)：一个可调用对象。调用它可以得到样式，也可以从中读取 [`variants()`](#variants)。需要 class name 时，把它传给 [`createClassName`](#createclassname) 返回的辅助函数。如果提供了 `config.slots`，返回的则是 `EvSlotsFunction<N, T>`，详见 [Slots](#slots)。

### `button(variants)` [#call]

调用 variant 函数，得到某个组合的样式。把结果传给 `css` prop 或 Emotion 的 `css()`。

```tsx
import type { ComponentPropsWithoutRef } from 'react';
import type { VariantProps } from 'emotion-variants';

type ButtonProps = ComponentPropsWithoutRef<'button'> & VariantProps<typeof button>;

function Button({ size, color, ...rest }: ButtonProps) {
  return <button css={button({ size, color })} {...rest} />;
}
```

```tsx
<Button>Uses defaultVariants</Button>
<Button size="large" color="primary">Large primary</Button>
```

值按键用 `??` 解析，所以省略或为 `undefined` 的值会回退到 `defaultVariants`。正因如此，上面的 `Button` 可以不加判断地直接透传可选 props。`false` 和 `0` 是真正的值，会被原样使用。

运行时 `null` 也会回退，但 `EvVariants` 不包含它：在 `strictNullChecks` 下，`button({ size: null })` 会报类型错误。请在调用前把 `null` 转换为 `undefined`。

```typescript
button({ size: undefined }); // 与 button() 相同
```

既没有 prop 也没有默认值的维度会被完全跳过。

#### 参数

- `variants` (`EvVariants<T>`，可选)：variant 值。每个键都是可选的。使用 [`createEv`](./create-ev.mdx) 创建的 `ev` 时，值也可以是[响应式的](./create-ev.mdx#responsive-values)。

#### 返回值

(`SerializedStyles[]`)：始终是数组，即使只匹配一个样式。样式的顺序是：`base`，然后是按维度声明顺序排列的匹配 `variants` 项，最后是按数组顺序排列的匹配 `compoundVariants`。发生 CSS 冲突时后者生效，传入键的顺序没有影响。

### `createClassName(css)` [#createclassname]

下面的 class name 辅助函数来自 `createClassName`。它接收用来注入样式的 Emotion `css` 函数，所以只需设置一次并导出这些辅助函数：

```ts
import { css } from '@emotion/css';
import { createClassName } from 'emotion-variants';

export const { className, classNameMap } = createClassName(css);
```

`emotion-variants` 自身从不导入 `@emotion/css`。只有用到这些辅助函数时才需要安装它，至于该传入哪个 `css`，请参阅 [Cache 与服务端渲染](#caches)。

### `className(button, variants)` [#classname]

当你需要普通的 class 字符串而不是 `css` prop 时，使用 `className()`，例如非 React 环境、只接受 `className` 的第三方组件，或测试断言。它会把 `base`、匹配的 variants **以及**匹配的 compound variants 合并成一个 class。

```tsx
<button className={className(button, { size: 'large', color: 'primary' })}>Click me</button>;

// defaultVariants 的应用方式与 button() 完全相同。
className(button);
```

#### 参数

- `button` (`EvFunction<T>`)：`ev()` 返回的函数。
- `variants` (`EvVariants<T>`，可选)：variant 值。每个键都是可选的。

#### 返回值

(`string`)：覆盖整个组合的一个 class name。

### `classNameMap(button)` [#classnamemap]

各个 class name 的查找表：`base` 一个，每个 variant 值各一个。适合与自行构建 class 列表的代码组合使用，或用来查看生成了什么。

```typescript
const button = ev({
  base: {
    padding: 10,
  },
  variants: {
    size: {
      small: {
        fontSize: 12,
      },
      large: {
        fontSize: 16,
      },
    },
    outlined: {
      true: {
        border: '1px solid',
      },
    },
    level: {
      1: {
        zIndex: 1,
      },
    },
  },
});

classNameMap(button).base; // 'css-abc123'
classNameMap(button).variants.size.small; // 'css-def456'
```

键使用值的字符串形式，所以 Boolean 和数字维度要以 `true` 和 `1` 读取：

```typescript
classNameMap(button).variants.outlined.true;
classNameMap(button).variants.level[1];
```

在第一次调用 `classNameMap(button)` 之前，不会向文档注入任何样式，并且结果会被缓存：只使用 `css` prop 的代码不会为此付出任何开销。

```typescript
classNameMap(button) === classNameMap(button); // true
```

<Callout type="warn">

`classNameMap()` 只覆盖 `base` 和单个 variant 值。**这里不包含 compound variants**，因为组合没有对应的键。需要 compound 样式时，请使用 [`className()`](#classname)。

拼接这些 class 的结果接近调用函数，但并不等价。`classNameMap()` 会先注入 `base`，再按轴的声明顺序注入各个 variant。因此无论你以什么顺序列出这些 class，variant 都会胜过 `base`，后声明的轴也会胜过先声明的轴。不过，如果另一个 `ev()` 已经注入了完全相同的样式，这个 class 会保持在先前注入的位置。需要结果与函数一致时，请使用 [`className()`](#classname)。

配置中没有 `base` 时，`base` 为空字符串。

</Callout>

#### 返回值

(`EvClassNameMap<T>`)：`{ base, variants }`，其中 `variants[axis][value]` 是一个 class name。

### `button.variants()` [#variants]

按声明顺序返回维度名称。用来生成 Storybook 的 argTypes 或 props 表格很方便。

```typescript
const button = ev({
  variants: {
    size: {
      small: {},
      large: {},
    },
    color: {
      primary: {},
      secondary: {},
    },
  },
});

button.variants(); // ['size', 'color']
```

没有 `variants` 的配置返回 `[]`。

#### 返回值

(`Array<VariantKeys<T>>`)：维度名称。每次调用都返回同一个数组实例，请把它当作只读。

### Slots [#slots]

当组件由多个元素组成时，用 `config.slots` 代替 `config.base`。此时 variant 值和 compound 的 `style` 都以 slot 名为键，调用会为每个 slot 返回一个样式函数。

```tsx
const card = ev({
  slots: {
    root: {
      padding: 16,
    },
    title: {
      fontWeight: 600,
    },
  },
  variants: {
    size: {
      small: {},
      large: {
        root: {
          padding: 24,
        },
        title: {
          fontSize: 20,
        },
      },
    },
  },
  compoundSlots: [
    {
      slots: ['root', 'title'],
      style: {
        margin: 0,
      },
    },
  ],
  defaultVariants: {
    size: 'small',
  },
});

const { root, title } = card({
  size: 'large',
});

<section css={root()}>
  <h3 css={title()}>Title</h3>
</section>;
```

每个 slot 函数接收与整体调用相同的 variants。每个维度的值依次从 slot 的 props、调用时的 props、`defaultVariants` 中解析，compound 条目则按每个 slot 解析出的值分别匹配。

一个 slot 的样式顺序是：它在 `slots` 中的条目、匹配的 `variants` 项、匹配的 `compoundVariants`，最后是匹配的 `compoundSlots`。

class name 辅助函数与普通形式有两处不同：

- `className(card, variants)` 为每个 slot 返回一个 class name，形如 `{ root: string, title: string }`。
- `classNameMap(card)` 会报类型错误，并且会抛出错误。

`card.variants()` 保持不变。

`config.base` 不能与 `config.slots` 同时使用，并且凡是引用 slot 的地方都只接受已声明的 slot 名。两者都会报类型错误。

#### 返回值

(`EvSlotsFunction<N, T>`)：调用后返回 `{ [slot]: (slotVariants?) => SerializedStyles[] }`。

完整讲解请参阅 [Slots](./slots.mdx)。

### extend [#extend]

把另一个 `ev()` 结果传给 `config.extend`，即可在其基础上构建。新函数会继承父函数的样式、variants、compound variants 和 default variants，父函数本身不会改变。

```ts
const button = ev({
  base: {
    padding: '10px 20px',
  },
  variants: {
    size: {
      small: {
        fontSize: 12,
      },
      large: {
        fontSize: 16,
      },
    },
  },
  defaultVariants: {
    size: 'small',
  },
});

const iconButton = ev({
  extend: button,
  base: {
    display: 'inline-flex',
  },
  variants: {
    size: {
      large: {
        width: 48,
      },
    },
    round: {
      true: {
        borderRadius: '50%',
      },
    },
  },
});

iconButton({
  size: 'large',
  round: true,
});
// padding, display, font-size, width, border-radius
```

在每一步中，父函数的样式都排在子函数之前，所以完整顺序是：

1. `base`：先父后子
2. 匹配的 `variants` 项：逐个维度处理，每个值先父后子
3. 匹配的 `compoundVariants` 项：先父后子

继承的维度保持原有位置，子函数的新维度排在后面，这也是 `iconButton.variants()` 返回的顺序。`defaultVariants` 按维度合并，子函数的值优先。子函数的 `compoundVariants` 和 `defaultVariants` 可以引用继承的维度和值。

所有 compound variant 都排在所有 variant 样式之后，所以父函数的 compound variant 仍会胜过子函数为同一 variant 值声明的样式。

使用 [slots](#slots) 时，父函数和子函数都必须是 slot 函数。子函数的 `slots` 会追加到父函数的 slots 上，没有 `slots` 的子函数则沿用父函数的。`compoundSlots` 会与 `compoundVariants` 一起被继承。

以下两种情况下，`ev()` 运行时 `extend` 会抛出错误：

- 传入的值不是 `ev()` 结果。如果它确实来自 `ev()`，很可能是安装了两份 `emotion-variants`。
- 带 `slots` 的配置扩展了不带 `slots` 的函数。这同样会报类型错误；父函数有 `slots` 时子函数使用 `config.base` 也会报类型错误。

完整讲解请参阅 [Extend](./extending.mdx)。

## Cache 与服务端渲染 [#caches]

`className()` 和 `classNameMap()` 会把样式注入到你传给 [`createClassName`](#createclassname) 的 `css` 函数所属的 cache 中。如果用的是 [`@emotion/css`](https://emotion.sh/docs/@emotion/css) 的 `css`，那就是一个独立于 `@emotion/react` 的全局 cache。它会忽略 `CacheProvider` 的 `key`、`nonce` 等选项，并且两个 cache 不共享插入顺序。

<Callout type="warn">

在两个 cache 相互独立的情况下，避免在同一个元素上同时使用 `css={button(...)}` 和 `className={className(button, ...)}`。覆盖结果可能不符合预期。

</Callout>

该传入哪个 `css`，取决于在哪里需要 class：

| 需要 class 的位置 | 传入的 `css` |
|---|---|
| 仅在客户端渲染的应用 | `@emotion/css` 的 `css`，并[共享同一个 cache](#share-one-cache) |
| CSP `nonce`、Shadow DOM 或自定义 `key` | [自己创建的实例](#custom-instance)的 `css` |
| 服务端渲染，渲染过程中 | [`ClassNames`](#server-rendering) 提供的 `css` |
| 服务端渲染，React 之外 | `@emotion/css` 的 `css`，并用 [`@emotion/server`](#server-rendering) 提取 |

### 共享同一个 cache [#share-one-cache]

在客户端渲染的应用中，把 `@emotion/css` 的 cache 交给 `@emotion/react`。这样 `css` prop 和 class name 辅助函数都会写入同一个 cache，共用一个插入顺序。

```tsx
import { cache } from '@emotion/css';
import { CacheProvider } from '@emotion/react';

<CacheProvider value={cache}>
  <App />
</CacheProvider>;
```

### 使用 `nonce`、`container` 或自定义 `key` [#custom-instance]

用 [`@emotion/css/create-instance`](https://emotion.sh/docs/@emotion/css#custom-instances) 创建一个实例，并传入它的 `css`。同一个 `cache` 也可以交给 `CacheProvider`。

```tsx
import createEmotion from '@emotion/css/create-instance';
import { createClassName } from 'emotion-variants';

export const emotion = createEmotion({
  key: 'app',
  nonce,
});

export const { className, classNameMap } = createClassName(emotion.css);
```

### 服务端渲染 [#server-rendering]

`@emotion/css` 的 cache 存活于整个服务端进程，而不是单个请求，所以要用 [`@emotion/server`](https://emotion.sh/docs/ssr#advanced-approach) 提取其中的样式。如果只收集 `@emotion/react` 的 cache，输出的 HTML 会缺少 `className()` 和 `classNameMap()` 的规则，首次绘制在 hydration 之前都没有样式。

在无法进行这种提取的场景中，例如 Next.js App Router 的流式渲染，可以用 `@emotion/react` 的 `ClassNames` 提供的 `css`，在渲染过程中创建辅助函数。样式会进入与 `css` prop 相同的 cache，每次请求都随 HTML 一起发送，并且不需要 `@emotion/css`。

```tsx
import { ClassNames } from '@emotion/react';
import { createClassName } from 'emotion-variants';

<ClassNames>
  {({ css }) => {
    const { className } = createClassName(css);
    const slots = className(card, {
      size: 'large',
    });

    return (
      <section className={slots.root}>
        <h3 className={slots.title}>Title</h3>
      </section>
    );
  }}
</ClassNames>;
```

`classNameMap()` 按每次 `createClassName` 调用分别缓存，所以在这里每次渲染都会重新生成。在渲染过程中请使用 `className()`。
